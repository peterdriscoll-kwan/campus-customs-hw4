- **Prompt submitted:** "Did the github repo maximize the use/calling of LLMs and agentic AI?" → gave an honest audit: the chat agent itself is genuinely agentic throughout (grounded tool calls, personalization, model escalation, self-correcting guardrail), while catalogue reads, auth, cart state, and the client-side filter bar deliberately don't call an LLM (correctly — using one there would be slower/non-deterministic/needlessly expensive, not "more AI"). Flagged one legitimate gap: `search_products` only did literal keyword/token-overlap matching, so natural-language queries with no shared words (e.g. "something cozy for game day") would return nothing relevant.
- **Follow-up prompt:** "Yes, build the semantic search upgrade!"
- **Evidence of work:** Tried wiring real vector embeddings first (`text-embedding-3-small`/`-large`/`ada-002` via Portkey's `/v1/embeddings`) — every model name came back the same error, since this Portkey account's config routes all of them to the `gpt-5.6-luna` chat deployment regardless of what's requested, and that deployment doesn't support embeddings. Pivoted to an LLM-based semantic reranker instead: added `backend/semantic_search.py` (a small dedicated PydanticAI agent judging relevance by meaning over a compact catalogue list) and `backend/portkey_client.py` (shared client factory, refactored out of `agent.py` to avoid duplicating Portkey setup). `search_products` in `tools.py` is now async and merges the semantic pass with the original keyword pass (semantic order first, keyword hits filling any gaps), falling back cleanly to keyword-only if the semantic call ever fails. Verified concretely: for "something cozy to wear tailgating in the cold this weekend" (shares zero real keywords with the catalogue), the *old* system's top pick was the totally-irrelevant **Diving Left Chest Crewneck** (matched only on the stopword "the"); the *new* hybrid search returned genuinely relevant cold-weather layers (hoodies, fleece jackets, a heavyweight crewneck) — confirmed both via direct tool testing and live through the actual chat widget. Re-verified a plain keyword query ("show me some hoodies") still returns the same quality results, no regression. Documented the whole upgrade, including why embeddings didn't work on this account, in `output/harness.md`.
